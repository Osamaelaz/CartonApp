# نشر البرنامج عند العميل (Windows)

## أين تُحفظ الملفات

| ماذا | أين |
|---|---|
| ملفات التصدير (PDF / Excel) | `Documents\الليثي باك\التصدير\` للمستخدم الذي يشغّل البرنامج |
| إعدادات قاعدة البيانات `db.properties` | `%APPDATA%\LeithiPack\` (أي `C:\Users\<المستخدم>\AppData\Roaming\LeithiPack\`) |
| بيانات الشركة وكلمة المرور والعملاء والفواتير | داخل قاعدة بيانات PostgreSQL (جدول `app_settings` وباقي الجداول) |

من البرنامج: **الإعدادات ← النظام ← فتح مجلد التصدير**. وبعد كل تصدير يظهر المسار الكامل في رسالة التأكيد.
لا يُكتب أي شيء داخل `Program Files`.

## تجهيز جهاز التطوير لعمل ملف التثبيت (مرة واحدة)

1. JDK 25 (Temurin) و Maven — موجودان.
2. WiX Toolset 3.x — موجود (3.14).
3. نبني: `mvn clean package` (حوالي دقيقة) ← الناتج في `target\dist\Carton Accounting-1.0.0.exe` (حوالي 52 ميجا، يحتوي على Java فلا يحتاج تثبيت Java عند العميل).
   عند رفع رقم الإصدار غيّر `<version>` في `pom.xml` فقط؛ المعرّف الثابت للتحديث موجود في إعدادات jpackage.

## تجهيز جهاز العميل

1. **تثبيت PostgreSQL** (نفس إصدار 18 أو أحدث) وحفظ كلمة مرور المستخدم `postgres`. اترك المنفذ 5432. يعمل كخدمة تلقائيًا مع Windows.
2. **إنشاء قاعدة البيانات** (مرة واحدة): من pgAdmin أو من موجه الأوامر:
   `psql -U postgres -c "CREATE DATABASE carton_accounting ENCODING 'UTF8'"`
3. **ملف الإعدادات**: انسخ `db.properties` إلى `%APPDATA%\LeithiPack\` وبداخله:
   ```
   db.url=jdbc:postgresql://localhost:5432/carton_accounting
   db.user=postgres
   db.password=<كلمة مرور postgres عند العميل>
   ```
   (إن لم يكن موجودًا، يعرض البرنامج رسالة تحدد المكان بالضبط.)
4. **تشغيل ملف التثبيت** `Carton Accounting-1.0.0.exe` ← اختصار على سطح المكتب وقائمة ابدأ.
5. **أول تشغيل**: يُنشئ البرنامج الجداول بنفسه (بدون أي بيانات تجريبية). الدخول بكلمة المرور `123` ثم **الإعدادات ← كلمة المرور** لتغييرها فورًا، و**بيانات الشركة** لضبط الاسم والعنوان والهاتف.
6. ابدأ بإدخال العملاء (مع المديونية السابقة) ثم المنتجات ثم الفواتير.

## النسخ الاحتياطي (مهم)

كل البيانات في قاعدة PostgreSQL. أمر نسخة احتياطية يدوي (يمكن جدولته من Task Scheduler):

```
pg_dump -U postgres -F c -f "D:\Backup\carton-2026-11-14.backup" carton_accounting
```

والاستعادة: `pg_restore -U postgres -d carton_accounting --clean "D:\Backup\carton-2026-11-14.backup"`.

## التحديثات لاحقًا

- تثبيت إصدار جديد فوق القديم لا يمس قاعدة البيانات ولا ملفات `%APPDATA%\LeithiPack` ولا التصدير.
- الأعمدة والجداول الجديدة تُضاف تلقائيًا عند أول تشغيل للإصدار الجديد.
- لتحديث فوق التثبيت القديم دون إزالته، يجب ثبات `--win-upgrade-uuid` في إعدادات جي باكيج.

## بديل: قاعدة البيانات على Neon (سحابية)

لا حاجة لتثبيت PostgreSQL عند العميل، لكن الجهاز يحتاج إنترنت أثناء العمل.

1. من لوحة Neon (المشروع ← Connect) انسخ رابط الاتصال **Direct connection** (ليس الـ Pooled، أي بدون `-pooler` في اسم الخادم).
2. ضعه في `%APPDATA%\LeithiPack\db.properties` كما هو:
   ```
   db.url=postgresql://USER:PASSWORD@ep-xxxx.region.aws.neon.tech/neondb?sslmode=require
   ```
   (يمكن أيضًا كتابة `jdbc:postgresql://...` مع `db.user` و`db.password` منفصلين.)
3. أول تشغيل ينشئ الجداول تلقائيًا. لا تحتاج `npm` ولا `neon init`؛ هذه للمشاريع المبنية بـ Node.
4. الأمان: كلمة مرور Neon تعطي وصولًا كاملًا للقاعدة — استخدم Role مخصصًا للبرنامج، ولا ترفع `db.properties` على Git.
5. أول اتصال بعد فترة خمول قد يتأخر بضع ثوانٍ (تشغيل الخادم)؛ مهلة الاتصال في البرنامج 30 ثانية.
6. النسخ الاحتياطي: Neon يوفّر استعادة لنقطة زمنية (Branch/Restore) بالإضافة إلى `pg_dump`.
7. لنقل البيانات الحالية من القاعدة المحلية: `pg_dump -Fc carton_accounting > a.dump` ثم `pg_restore --no-owner -d "<رابط Neon>" a.dump`.
